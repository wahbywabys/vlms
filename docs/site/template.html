01 / Architecture

Three engines, one record of competence

Each engine owns its domain services. They share an identity service, a Redis event backbone and PostgreSQL as the single system of record. Every interaction, virtual or physical, becomes an xAPI statement and moves the learner's competency profile.

Offline is a normal state

Every client-written row has a client-minted UUID and a client_mutation_id, so a tablet that reconnects after a shift can replay its outbox without creating duplicates.

Safety gates are first-class

Any rubric criterion can be a gate. Failing it fails the attempt whatever the score, and it never counts as positive competency evidence.

Postgres records, Redis broadcasts

A Redis outage slows live dashboards but loses nothing. The scale path is Redis Streams to Kafka and monthly telemetry partitions to a time-series store.

03 / UI/UX blueprint

Three screens, three places

Each screen is designed for where it is used: a noisy workshop floor, a learner's laptop or headset, and a director's office. Shared rules: touch targets of at least 44 px (56 px on the trainer tablet, for gloved hands), status shown by shape as well as colour, offline treated as a normal state, and right-to-left layouts supported for Arabic.

04 / React Three Fiber component

3D machine explorer, running

This is the production component from web/src/components/MachineExplorer.tsx, built and running live. Drag the exploded-view slider, tap a numbered pin, then try X-ray, Cutaway and Run. Each interaction emits the same telemetry shape the API ingests.

Staged disassembly

Each part has an explode vector and a stage on the slider, so the cowl and fan come off before the end shields and bearings, following the maintenance manual order.

Model-agnostic

Parts render whatever you give them. A glTF digital twin plugs in as render: () => <primitive object={nodes.Fan} />; the demo motor is procedural.

Tablet-ready

Damped motion keeps slider drags smooth, buttons are 40 px or larger, and the camera zooms out on portrait screens so the exploded assembly stays in frame.

05 / Node.js API

Rubric evaluation & telemetry ingestion

Two endpoints in TypeScript (Express 5, zod, node-postgres, ioredis). The learner's V-Lab client streams batched events while the session runs, and a deterministic rubric engine scores the whole stream on submit.

POST /v1/vlab/sessions/:id/telemetry

  • Batches of up to 500 xAPI-shaped events with a client sequence number
  • Retries are idempotent; the session row is locked so concurrent batches serialise
  • Rejects events dated in the future, before the session, or after the exam time limit
  • Runs the rubric's safety-gate rules live and publishes violations to trainer tablets
  • In Guided mode it returns guardrail: "block" so the client stops the unsafe action

POST /v1/vlab/sessions/:id/evaluate

  • Re-scores the full stream: same input, same score, so auditors can reproduce it
  • Weighted criteria plus safety gates that fail the attempt outright
  • Writes the evaluation, appends competency evidence, raises learner levels (never lowers)
  • Virtual evidence alone caps at Autonomous; Master needs workplace verification
  • Idempotent: a second call returns the stored result
